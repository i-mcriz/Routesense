# RouteSense AI: Web Application Architecture

## 1. Frontend Architecture

**Technology:** Vanilla HTML5, CSS3, JavaScript with Leaflet.js for mapping.

**Layout:** A full-screen, map-first interface with glassmorphic floating panels:
- **Header** (top): Brand + real-time status indicator
- **Legend** (top-left): Risk level and route type indicators
- **Flood Simulation** (bottom-left): Intensity, water level, radius controls
- **RouteSense Routing** (bottom-right): Profile selector, origin/destination, route trigger
- **Route Impact** (top-right, appears after routing): Live metrics comparison

**Design Language:** Dark monochrome base with semantic risk colors (green/amber/red) and accent blue. Glassmorphism panels with `backdrop-filter: blur()`. Inter + JetBrains Mono typography.

**Map Tiles:** CartoDB Dark Matter (`dark_all`) for cinematic contrast with particle overlays.

## 2. Backend Architecture

**Technology:** Flask (Python) serving both the API and the static frontend.

**Endpoints:**
| Endpoint | Method | Purpose |
|---|---|---|
| `/` | GET | Serve frontend |
| `/api/health` | GET | System status, graph stats |
| `/api/risk-map` | GET | GeoJSON of study area risk features |
| `/api/route` | POST | Compute normal + RouteSense routes |
| `/api/simulate-flood` | POST | Return affected road segments |

**Startup:** On launch, the server loads the full 496k-feature GeoJSON, subsets to the Thrissur study area (10,153 segments), pre-builds a NetworkX graph (57,611 nodes / 60,567 edges), and caches the risk-map payload.

## 3. Existing ML Risk Model

The road-risk predictions used by the web app are generated by the existing ML pipeline (`scripts/train_models.py`). The best model is Random Forest with ~66% accuracy on prototype synthetic labels. The web app reads predictions directly from `outputs/routesense_road_risk.geojson` — it does NOT retrain or modify the ML model.

## 4. Personalized Routing

Three evacuation profiles are supported:

| Profile | LOW mult | MED mult | HIGH mult | Slope Penalty | Avoids Steps | Avoids Footway |
|---|---|---|---|---|---|---|
| General | 1.0 | 2.0 | 5.0 | None | No | No |
| Elderly / Mobility-Limited | 1.0 | 3.0 | 8.0 | 0.5× | Yes | Yes |
| High-Risk Emergency | 1.0 | 4.0 | 12.0 | None | No | No |

Edge cost formula:
```
routesense_cost = distance × risk_multiplier + slope_penalty + accessibility_penalty
```

## 5. Flood Simulation

The flood simulation is a **prototype spatial overlay**, not a hydrological model. When activated:

1. User places a flood center (Shift+click or map click)
2. User adjusts intensity (0–1), water level (0–5m), and radius (500–5000m)
3. For each road edge within the flood radius:
   - `proximity = 1.0 - (distance_to_center / radius)`
   - `elev_factor = max(0, 1.0 - elevation / 500)`
   - `flood_penalty = proximity × intensity × elev_factor × water_level`
   - If penalty > 0.7 → risk becomes HIGH
   - If penalty > 0.3 → risk becomes at least MEDIUM

This transparently documented rule simulates how lower-elevation roads closer to a flood epicenter would face higher risk.

## 6. Real-Time Route Update Process

1. User adjusts flood parameters or changes profile
2. Frontend sends POST to `/api/route` with current state
3. Backend recomputes edge weights (applying flood penalties)
4. Backend runs Dijkstra twice: `distance` for normal, `routesense_cost` for safe route
5. Backend returns both route geometries + comparison metrics
6. Frontend renders routes and updates impact panel

## 7. Particle Visualization

Roads are rendered as **particle fields** rather than solid lines:
- Each LineString is sampled at intervals based on risk level
- HIGH risk: dense particles (step=0.0004°), radius=2px, 65% opacity
- MEDIUM risk: moderate particles (step=0.0007°), radius=1.6px, 50% opacity
- LOW risk: sparse particles (step=0.0012°), radius=1.2px, 35% opacity

The RouteSense route features animated traveling particles (8 dots) that flow along the path toward the destination, visually communicating active evacuation guidance.

## 8. Data Flow

```
outputs/routesense_road_risk.geojson  (ML predictions)
        │
        ▼
  backend/app.py  (loads → subsets → builds graph → caches)
        │
        ├── /api/risk-map  →  Frontend particle renderer
        │
        └── /api/route     →  Dijkstra (normal + risk-weighted)
                                    │
                                    ▼
                            Frontend route renderer
                            + animated particles
                            + impact metrics
```

## 9. Limitations

- **Prototype labels:** Risk predictions are based on synthetic/heuristic labels, not verified flood history.
- **Flood simulation:** Uses a spatial proximity rule, not hydrological modeling.
- **Study area:** Routing is limited to the Thrissur demonstration area for computational feasibility.
- **Graph precision:** Road intersections are detected by coordinate matching, which may miss some connections due to floating-point differences.
- **Not for operational use:** This system must not be used as an actual emergency navigation tool.
